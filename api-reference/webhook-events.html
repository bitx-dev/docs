Webhook Event Data ​

This reference is generated from the backend notification DTOs, event constants, and event-to-payload parser. Producer-specific notes explain the behavior of the current checkout. Use the webhook guide for signature verification and the management reference for configuration and testing.

Download the JSON Schema and complete example deliveries. These describe merchant deliveries to your URL; engine-to-BITXpay callbacks have a different contract.

Reading the payload ​

All fields in the tables are inside the outer delivery's data object. “Always” means the JSON field is serialized even when it is an empty string, zero, or false; it does not promise a non-empty value. “When set” means the Go DTO uses omitempty. Examples include serialized defaults and represent the producer described in the notes, except DTO-only events, whose examples are test fixtures.

The outer fields are id, event_type, event_id, timestamp, and data. Only the outer timestamp is consistently RFC 3339; time strings inside data follow each producer. Amounts below are strings. Keep their event-specific denomination rather than treating every amount as fiat or every string as token base units.

Custom webhook_metadata appears only in DTOs that declare it: payment_link.created, subscription.created, and subscription_invitation.created. The notification worker does not merge metadata, order_id, receipt_number, cart, or arbitrary REST response fields into other events.

payment.succeeded ​

Engine checkout emits this for a completed link. payment_id is the link UUID and link_id is its deterministic INV-... reference. amount/currency are the link's invoice denomination, not the raw token pay_amount. asset and fees are currently empty strings. Legacy listeners can instead use the payment token denomination. Overpaid engine orders emit transaction.overpaid rather than this event.

event_codestringAlwaysSame event code as the outer event_type.
customer_emailstringAlwaysNotification recipient email; may be the latest payer, customer, or merchant depending on the producer.
customer_namestringAlwaysNotification recipient display name.
merchant_namestringWhen setMerchant display name when supplied by the producer.
link_idstringAlwaysPayment link UUID for link creation; INV-... display reference for engine payment status events.
payment_idstringAlwaysPayment link UUID for engine payment events; dispute UUID for refund events. See event notes.
amountstringAlwaysAmount string in this event's currency; see event notes for denomination.
currencystringAlwaysAmount denomination, which can be an invoice currency or a paid token symbol depending on the event.
transaction_hashstringAlwaysTransaction hash when available; may be an empty string.
networkstringAlwaysNetwork name, or chain ID as a string when a name cannot be resolved.
assetstringAlwaysProducer-supplied asset/network label; currently empty for engine success/failure notifications.
feesstringAlwaysProducer-supplied fee string; currently empty for engine success/failure notifications.
received_atstringAlwaysProducer event time; engine success uses Go Time.String(), not the outer RFC 3339 format.

They are not fiat invoice amounts or raw base-unit integers. The engine producer includes payment_id, network, payment_url, and payment_date_time. Total = partial + remaining. The status producer leaves dispute_id empty; the liability producer supplies its dispute UUID, so more than one notification can describe the same overpayment. frontend_url is currently empty for both engine producers. Legacy paths can populate different link/reference fields.

payment_idstringWhen setPayment link UUID for engine payment events; dispute UUID for refund events. See event notes.
expected_amountstringAlwaysExpected amount; engine overpayment events use display token units.
